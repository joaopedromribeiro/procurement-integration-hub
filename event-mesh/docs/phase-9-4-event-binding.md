# Phase 9.4 — PIH Event Binding

Status: **EVENT BINDING ACTIVE / EXTERNAL PUBLICATION ENVIRONMENT-BLOCKED**. This record reflects owner-verified ADT and `/IWXBE/CONFIG` observations, not an exported Event Binding source mirror or a successful broker run. The Phase 6–8 HTTP delivery path remains authoritative and unchanged.

## Objective and active binding

Bind the Phase 9.3 RAP DeliveryIntent event to a PIH-owned external business-event type without reusing shared SAP event infrastructure. The owner created and activated this Event Binding in ADT:

| Field | Active value |
| --- | --- |
| Event Binding | `ZJPEBPODLVREQ` |
| Package | `ZJP_PROC_HUB` |
| Description | `PIH Purchase Order Delivery Requested Event Binding` |
| Type Namespace | `zjp` |
| SAP Object Type | `PurchaseOrder` |
| Operation | `DeliveryRequested` |
| Generated external Type | `zjp.PurchaseOrder.DeliveryRequested.v*` |
| Event version | Major `0001` (generated by SAP), minor `0`, patch `0` |
| RAP Entity | `ZJP_I_DELIVERYINTENT` |
| RAP Entity Event | `PURCHASEORDERDELIVERYREQUESTED` |

The ADT warning that the custom `DeliveryRequested` operation did not previously exist was nonblocking; activation succeeded. The exact external Type above is the A4H-generated value, not a guessed `v1` or `v0001` spelling. It does not establish a published topic, message envelope, or delivered broker event.

The internal event remains `ZJP_I_DeliveryIntent~PurchaseOrderDeliveryRequested`. `DeliveryUUID` is the RAP event entity key; `%param` contains `PurchaseOrderUUID`, `OrderRevision`, and `PayloadHash` only. The target compiler rejected adding `DeliveryUUID` to the abstract parameter. This binding does not change the durable DeliveryIntent or the Phase 7 coordinator.

## SAP tooling and isolation

The owner opened `/IWXBE/CONFIG`. It exposes Outbound Binding Configuration, Channel Configuration, AMQP channels, outbound/inbound bindings, subscriptions, service-key-based setup, and Check Connection. This proves SAP-side tooling is available, **not** a working PIH Event Mesh connection.

Visible existing channels include `CHANNEL_POC_VALGROUP`, `EDA_SAP_BTP`, `EVENT_MESH1`, `SEND_EVENT_TO_BTP`, `SENDEVENTSTOBTP`, `SENDWTOBPA`, and `ZJFB_EVENT_ENABLEMENT`. The example `CHANNEL_POC_VALGROUP` uses AMQP topic space `em/lab2dev/sap`, daemon user `M.GOMES`, and an existing `sap/s4/beh/product/v1/Product/*` outbound binding. These are shared artifacts with no demonstrated PIH ownership. The owner deliberately did **not** modify or reuse any such channel, binding, topic space, or credentials and did not add the PIH event to them.

The currently inspected BTP environment does not expose an assignable Event Mesh broker/service plan for PIH. This is an environment-specific limitation, **not** a claim that all Trial environments lack Event Mesh. Because no PIH-owned service key exists, the owner did not create an AMQP channel using shared infrastructure.

## Intended external route and next gate
