## B2 connectivity incident and final replay

The first CSRF fetch (`MessageFlow_705`) timed out after 10,000 ms to `connectivityproxy.internal`. The existing Phase 7 exception subprocess answered HTTP 503 `UPSTREAM_CSRF_UNAVAILABLE`; it did not perform the SAP business POST. Cloud Connector showed the backend `pih-s4h2023:44323` reachable, the OData resource exposed, and a diagnostic destination reachable, but Integration Suite's Cloud Connector connectivity test failed. SCC `scc_core` traced a DNS timeout resolving `connectivitytunnel.cf.us10-001.hana.ondemand.com` through resolver `192.168.15.1`. After the owner corrected the SCC host's DNS resolvers and restarted SCC, the connectivity test returned **Successfully reached Cloud Connector**. This was a local/shared-environment DNS tunnel failure, **not an application-code defect**.

The owner then replayed the **already-applied current** `ACCEPTED` response `11108278-d0b8-4db6-b52a-9d57ab7adc2f`, version 2, for portal order `9efeb598-03cf-44f8-81e5-24c68bcbc176` / source order `37fc3fa8-eb2d-1fd1-ad92-f2fc9e60f34d`. Through the CSRF GET, Cloud Connector and bound `applySupplierResponse` POST, SAP returned **HTTP 204 No Content** after the `INTEGRATOR` correction. The diagnostic CSRF receiver timeout of 60,000 ms was restored to **10,000 ms**, and the same current-response replay returned **HTTP 204 again**. This is idempotent-replay evidence; **no new supplier decision or changed business state is claimed**.
